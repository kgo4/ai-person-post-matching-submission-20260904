## 项目简介

多源异构岗位与能力图谱平台，围绕人工智能、大数据、智能系统、物联网等新一代信息技术领域，构建从岗位数据采集到人才能力评估的完整闭环。

平台融合岗位 JD、简历、AI 测试、AI 面试、PMS 项目材料、行业知识资料等多源异构数据，通过数据清洗、去噪、去重、语义分析、向量检索、Agent 协同和知识图谱技术，实现：

- 新兴岗位发现与定义
- 既有岗位能力动态更新
- 岗位能力图谱构建
- 简历智能解析
- 人员能力评估
- AI 测试与 AI 面试
- 人岗匹配与差距分析
- 学习路径规划
- 岗位演化趋势分析
- 能力证据治理与可追溯管理

平台的核心目标是将传统的静态关键词匹配，升级为基于能力、证据和语义理解的动态人才分析系统。

## 核心业务闭环

```text
多源数据采集
      ↓
数据清洗、去噪、去重
      ↓
岗位 JD 解析与能力提取
      ↓
岗位能力表沉淀
      ↓
岗位能力图谱构建
      ↓
新兴岗位发现与岗位演化
      ↓
简历解析与人员能力提取
      ↓
AI 测试与 AI 面试核验
      ↓
能力证据审核与等级确认
      ↓
人员正式能力表入库
      ↓
人岗匹配、差距分析与学习路径推荐
```

## 主要功能

### 1. 岗位 JD 智能解析

支持岗位 JD 单条录入和 Excel 批量导入，自动提取：

- 岗位名称
- 岗位方向
- 岗位级别
- 核心职责
- 任职要求
- 技术栈
- 技能点
- 能力等级
- 能力权重
- 行业应用场景

岗位能力表是岗位业务的主要数据源，保证岗位实际需求能够独立支撑后续分析。

### 2. 岗位能力图谱

平台支持两种图谱视图：

#### 岗位视图

以岗位为中心，向外连接岗位所需的技术栈和技能点。

```text
岗位
 ├── Java
 ├── Spring Boot
 ├── MySQL
 ├── Redis
 └── 分布式系统
```

#### 技术栈视图

以技术栈为中心，向外连接使用该技术栈的岗位。

```text
Java
 ├── Java AI 应用开发工程师
 ├── 后端开发工程师
 └── 分布式系统工程师
```

图谱展示以岗位能力表为主要依据，不依赖系统标签库才能正常显示。

### 3. 新兴岗位发现与定义

用户填写岗位名称、岗位描述、主要职责和所属行业后，系统结合：

- 用户填写的岗位信息
- 岗位能力表
- 系统标签库
- 向量语义检索结果
- 行业知识资料

推荐该岗位可能需要的能力标签。

推荐结果支持人工修改，并可一键创建岗位。

岗位能力只能引用系统中已经存在的岗位能力或标准能力，不会在该流程中随意生成不存在的能力。

### 4. 岗位演化分析

岗位演化 Agent 用于分析岗位能力随市场趋势的变化，输出：

- 新增能力
- 删除能力
- 修改能力
- 能力等级变化
- 能力权重变化
- 变化原因
- 来源证据
- 行业趋势说明

支持上传行业白皮书、技术报告等资料，经过索引、清洗和知识检索后，为岗位演化分析提供辅助依据。

### 5. 简历智能解析

支持 PDF、Word 等常见简历格式，提取：

- 基本信息
- 教育经历
- 工作经历
- 项目经历
- 技术栈
- 技能点
- 项目成果
- 能力证据

简历解析结果进入人员能力评估流程，最终以人员正式能力表作为人员业务数据来源。

### 6. AI 测试与 AI 面试

AI 测试和 AI 面试主要用于核验简历中提取的能力：

- AI 测试负责生成测试题并核验能力
- AI 面试负责围绕能力进行提问和追问
- 语音回答支持 ASR 转写
- 视觉模型用于采集面试视觉证据
- 每项能力均保留对应证据和来源

AI 不直接替代审核流程，而是为能力等级确认提供结构化证据。

### 7. 人员能力评估与 Harness

人员能力评估采用证据驱动的审核机制。

当某项能力同时满足：

- 简历已提取能力
- AI 测试完成核验
- AI 面试完成核验
- 存在有效证据
- 证据来源可解析、可追溯

系统可以自动通过 Harness，进入最终能力等级确认中心，计算最终等级并写入人员正式能力表。

自动通过的记录只用于留痕，不会再次进入人工审核。

不满足自动通过条件的能力进入人工审核；缺少有效证据的能力会被阻断或标记为待处理。

### 8. 人岗匹配与差距分析

匹配机制综合考虑：

- 精确名称匹配
- 名称规范化
- 别名匹配
- 技术栈关联
- 语义相似度
- 能力等级
- 能力权重
- 证据可信度

能力名称不完全一致时，不会直接判定为 0 分，而是根据归一化、别名和语义相似度合理给分。

岗位能力表和人员正式能力表是匹配业务的主要数据源，系统标签库仅作为辅助召回信息。

### 9. 学习路径规划

根据人员能力差距和目标岗位要求，生成：

- 待提升能力
- 能力提升顺序
- 前置能力
- 学习阶段
- 推荐学习资源
- 学习时长
- 阶段测试
- 能力提升确认结果

学习路径只负责学习建议和资源编排，不会直接修改人员正式能力或岗位能力。

## Agent 协同架构

平台采用多 Agent 协同方式，不同 Agent 负责不同业务领域。

| Agent | 主要职责 |
|---|---|
| 岗位能力提取 Agent | 从岗位 JD 中提取岗位能力 |
| 岗位演化 Agent | 分析岗位能力变化和行业趋势 |
| 人岗匹配 Agent | 解释匹配结果和差距事实 |
| 学习路径 Agent | 生成能力提升路径和学习建议 |
| PMS 分析 Agent | 从项目材料提取能力证据 |
| AI 测试 Agent | 核验人员能力 |
| AI 面试 Agent | 通过问答和面试证据核验能力 |
| 证据治理 Agent | 辅助处理能力证据和来源信息 |

不同 Agent 使用独立的业务契约和输出结构，避免不同业务之间相互污染。

## Agent 通信与 JSON 约束

平台保留统一的底层 JSON 防护能力，包括：

- JSON 格式校验
- Markdown 清理
- 非法 JSON 重试
- 字段类型校验
- 空结果检测
- 业务字段校验
- 错误原因记录
- 确定性规则兜底

同时为不同业务 Agent 配置独立的 JSON 业务契约：

```text
岗位演化 Agent
POST_EVOLUTION

岗位能力提取 Agent
POST_ABILITY_EXTRACTION

人岗匹配 Agent
MATCHING_ANALYSIS

学习路径 Agent
LEARNING_PATH

PMS 分析 Agent
PMS_ABILITY_ANALYSIS
```

每个 Agent 均有自己的：

- 输出字段说明
- 正确示例
- 空结果结构
- 业务校验规则
- 拒绝原因
- 证据引用规则

Agent 返回的结构化结果必须经过校验后才能进入业务流程。

## 系统标签库定位

系统标签库用于跨岗位能力标准化和辅助召回，不是岗位能力表或人员正式能力表的替代品。

### 岗位能力表

记录岗位真实需要的能力、技能点、技术栈、等级和权重。

### 人员正式能力表

记录人员已经确认的能力和最终能力等级。

### 系统标签库

用于维护：

- 标准能力名称
- 能力别名
- 能力引用次数
- 能力来源
- 能力热度
- 语义召回信息
- 标签词云
- 标签引用统计
- 标签热力图

系统标签库为空时，不应阻断岗位、人员、匹配和图谱等主业务。

## 数据与证据治理

平台对输入数据执行统一治理：

```text
原始数据
  ↓
格式解析
  ↓
文本清洗
  ↓
噪声过滤
  ↓
重复检测
  ↓
来源记录
  ↓
能力提取
  ↓
证据保存
  ↓
业务使用
```

每条能力结果尽量保留：

- 来源类型
- 来源编号
- 原始文本
- 解析记录
- 证据内容
- 置信度
- 创建时间
- 校验状态

所有关键 Agent 结果均可追踪到原始来源。

项目支持 Docker Compose 部署。

### 1. 准备环境

- Docker
- Docker Compose

- Redis

- Milvus
- Neo4j

## 项目特色

### 数据驱动

基于真实岗位 JD、简历、项目材料和行业资料构建能力数据。

### 多 Agent 协同

不同业务使用独立 Agent，职责清晰、相互隔离。

### JSON 结构化约束

统一底层防护，结合业务配置独立契约，提升输出稳定性。

### 证据可追溯

能力结果具备来源和证据，支持审核、复核和回溯。

### 主数据优先

岗位能力表和人员正式能力表是核心业务主数据，系统标签库只提供辅助能力。

### 异步解耦

耗时较长的 AI 分析、标签治理、向量索引等任务采用异步处理，避免阻塞主业务。

### 可扩展

系统可以扩展到更多新一代信息技术岗位和行业场景。
